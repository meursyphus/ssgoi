# Motion Analyzer — 요구사항

앱 화면 녹화 영상에서 페이지 전환의 타이밍을 뽑아, SSGOI가 쓰는 물리값(spring / inertia)으로
환산해 보고서로 내는 **스크립트 도구**를 만든다. 웹 앱이 아니다. 영상 하나를 넣으면 그 안의
전환을 전부 찾아 각각의 값을 낸다.

## 1. 배경과 목적

SSGOI의 페이지 전환은 스프링 물리(적분기)로 움직인다. 지금까지는 카카오톡·iOS·Material 같은
레퍼런스 앱을 녹화해 눈으로 보며 값을 맞췄고, 그 결과는 일관되지 않다. 목적은 **측정**이다:

- 녹화 영상에서 전환의 시작·끝, 나가는 페이지와 들어오는 페이지 각각의 진행 곡선을 잰다.
- 그 곡선에 SSGOI의 물리 모델을 맞춰 "우리 식" 값으로 낸다. 눈대중이 아니라 물리 로직으로.
- 사람이 읽는 보고서로 낸다. 어느 시간에 어떤 전환이 있었고, 그 전환의 값은 무엇인지.

## 2. 입력

- 화면 녹화 파일 한 개. iPhone/Android 기본 녹화(`.mov` HEVC/H.264, `.mp4`)를 그대로 받는다.
- 선택 인자: 전환의 방향 태그(forward/backward), 분석 해상도, 출력 경로.
- 한 영상에 전환이 여러 개 순차로 들어 있을 수 있다. 사용자가 구간을 잘라 주지 않아도 된다.

## 3. 출력 (보고서)

영상 하나당 보고서 하나. 사람이 읽는 형식(Markdown 또는 HTML)과 기계가 읽는 JSON을 함께 낸다.

### 3.1 타임라인 표

영상에서 찾은 전환을 순서대로 나열한다.

| # | 시작 (ms) | 끝 (ms) | 길이 | 나가는 페이지 | 들어오는 페이지 | 겹침 | 신뢰도 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 240 | 1 610 | 370 ms | 페이드 | 위로 슬라이드 + 페이드 | in이 out 30%에 시작 | 높음 |
| 2 | 3 880 | 4 300 | 420 ms | 축소 + 어둡게 | 아래에서 상승 | 동시 | 중간 |

### 3.2 전환별 상세

전환마다 다음을 낸다.

1. **해당 영상 구간** — 그 전환만 잘라 낸 클립(또는 프레임 스트립)과 시작·끝 프레임 이미지.
   보고서에서 표의 행을 보고 바로 그 구간을 확인할 수 있어야 한다.
2. **레이어별 진행률 곡선** — 나가는 페이지(out)와 들어오는 페이지(in)를 같은 시간축에 그린
   그래프. 측정점, 맞춘 곡선, 잔차를 함께. 공유 요소(카드가 커져서 상세가 되는 식)가 있으면
   별도 레이어(shared)로.
3. **우리 식 물리값** — 레이어마다:
   - 모델 종류: `spring` / `doubleSpring` / `inertia`
   - spring이면 `{ stiffness, damping }` (mass 1, 변위 0→1 정규화), doubleSpring이면 follower 비율까지
   - inertia면 `{ acceleration, resistance }`
   - 사람이 읽는 환산: 체감 duration(초)과 bounce (Apple 식: stiffness = (2π/D)², damping = 4π(1−bounce)/D)
   - 정착 시간(ms), 맞춤 오차(RMSE), "동등한 대안 모델"이 있으면 그 목록
   - SSGOI 내장 시맨틱 프리셋(`smooth` / `snappy` / `bouncy` / `gentle` / `swift` / `accelerate`)
     중 **가장 가까운 것과 오차**
4. **겹침(startAt)** — 들어오는 페이지가 나가는 페이지의 어느 진행률에서 시작했는지(0 = 동시,
   1 = 나가는 쪽이 끝난 뒤). 시간차(ms)도 함께.
5. **그대로 붙여 넣는 코드** — SSGOI 프리셋 오버라이드 형식 한 덩어리:

   ```ts
   axis({ type: "y" }, {
     override: {
       forward: (anim) => {
         anim.set("in",  { integrator: spring({ duration: 0.31, bounce: 0.25 }) });
         anim.set("out", { integrator: easeIn({ duration: 0.12 }) });
         anim.startAt = [0, 0.3];
       },
     },
   });
   ```

   프리셋 이름(`axis`, `drill`, …)은 도구가 추정해 제안하되 사용자가 바꿀 수 있게 인자로 받는다.
6. **재현 불가 요소** — 페이지와 다르게 움직인 요소(헤더 파랄랙스, 리스트 스태거 등)가 있으면
   "이 요소는 페이지 곡선을 따르지 않음"으로 목록만 낸다. 값을 맞추려 하지 않는다.

### 3.3 요약

영상 전체에 대해: 전환 개수, 방향별 평균 duration/bounce, 가장 가까운 프리셋 분포. 같은 앱의
영상 여러 개를 돌렸을 때 값이 얼마나 일관된지 비교할 수 있게 JSON에 같은 필드를 남긴다.

## 4. 기능 요구사항

### 4.1 전환 구간 자동 분할

- 프레임 간 변화량(픽셀 차 에너지)으로 움직임 구간을 찾는다. 임계값 넘는 연속 구간 하나가 전환
  하나다. 너무 짧은 구간(스크롤 튐, 터치 하이라이트)은 버린다.
- 사용자가 정지 상태로 기다린 구간이 전환 사이에 있으면 자연히 분리된다. 전환이 연달아
  붙어 있으면(뒤로 가기 직후 다시 진입) 방향 전환점에서 나눈다.
- 각 구간의 시작 = 움직임 직전 프레임, 끝 = 정지 첫 프레임. 실제 프레임 타임스탬프를 쓴다
  (프레임 번호 × 1/fps 아님. 가변 프레임레이트 대비).

### 4.2 레이어 분리 (나가는 페이지 / 들어오는 페이지 / 공유 요소)

- 전환 시작 프레임에 있다가 사라지는 것이 나가는 페이지, 끝 프레임에 있고 나중에 나타나는 것이
  들어오는 페이지, 내내 있으면서 움직이는 것이 공유 요소, 내내 있고 안 움직이면 상태바·탭바
  같은 고정 크롬(제외).
- 방법은 특징점 추적 + 궤적 군집이든 다른 것이든 상관없다. 요구는 결과: 레이어마다 위치(x, y),
  크기(scale), 불투명도(opacity) 곡선이 나와야 한다.
- 흰 배경끼리의 전환(텍스트만 움직임), 8 px 수준의 미세 이동도 잡아야 한다.
- 자동 분리가 애매하면 보고서에 신뢰도를 낮게 표시하고, 사용자가 관심 영역(ROI)을 인자로 줄
  수 있어야 한다.

### 4.3 물리 피팅 — 물리 로직으로

- 곡선을 베지어나 임의 easing으로 근사하지 않는다. **SSGOI가 실제로 쓰는 적분기 방정식**
  (semi-implicit Euler, 60 fps 고정 스텝, 정착 판정)으로 후보 곡선을 만들어 맞춘다. 그래야
  보고서의 값을 SSGOI에 넣었을 때 보고서의 곡선이 그대로 나온다.
- 후보 모델: spring, doubleSpring(follower 비율 0.5~2), inertia. 각 모델을 맞춘 뒤 **파라미터가
  적은 모델을 우선**한다(오차 차이가 5~10% 이내면 단순한 쪽).
- 한 레이어의 위치·크기·불투명도는 하나의 진행률로 함께 움직인다고 보고 **공동으로** 맞춘다.
- 시작 시각 오프셋(t0)을 자유변수로 두되 범위를 제한한다(−1~+3 프레임).
- 30 fps 녹화는 서로 다른 파라미터가 같은 곡선을 내는 경우가 흔하다. 그래서 (a) 60 fps 녹화를
  권장한다고 보고서에 표시하고, (b) 동등한 대안 모델을 항상 같이 낸다, (c) duration/bounce
  두 값만으로 맞추는 제약 모드를 제공한다.
- 피팅 오차(RMSE)와 잔차 그래프를 항상 낸다. 오차가 큰 전환은 표에서 눈에 띄게 표시한다.

### 4.4 겹침 측정

- 레이어별 시작 시각의 차이를 재고, 나가는 페이지의 맞춘 곡선에서 그 시각의 진행률을 읽어
  `startAt`으로 낸다. 들어오는 쪽이 나가는 쪽 정착 후에 시작하면 1.

### 4.5 보고서 생성

- 영상 하나 → 폴더 하나: `report.md`(또는 `.html`), `report.json`, 전환별 클립/프레임 이미지,
  곡선 그래프 이미지.
- 표의 각 행에서 해당 클립·그래프·코드로 바로 이어지게 링크한다.
- 같은 명령을 다시 돌리면 같은 결과가 나와야 한다(난수 시드 고정).

## 5. 비기능 요구사항

- **스크립트 도구.** `analyze <video> [--direction forward|backward] [--out dir] [--roi …]` 형태의
  CLI. 브라우저 UI 없음. 영상은 어디로도 전송하지 않는다.
- 분석 코어는 입력(프레임 배열)과 출력(JSON)이 분리된 순수 로직으로 두어, 나중에 다른 프론트
  (웹 페이지, 에디터)를 붙일 수 있게 한다. 디코더는 교체 가능해야 한다(ffmpeg 프레임 추출이든
  WebCodecs든).
- 60 fps 1초 전환 기준 수 초 안에 끝나야 한다.
- iPhone 기본 녹화(HEVC .mov)를 변환 없이 받는다.

## 6. 인수 기준

1. SSGOI 자체 데모(transition-lab)를 녹화해 넣으면, 설정해 둔 물리값이 오차 5% 이내로 다시
   나온다(폐루프). 겹침(`startAt`)도 ±0.05 이내.
2. 전환이 세 개 연달아 든 영상에서 세 구간이 전부 분할되고, 각 행에서 클립·그래프·값·코드로
   이어진다.
3. iOS 푸시, Material shared-axis, 카카오톡 탭 전환 녹화 세 종에서 나가는/들어오는 페이지가
   올바르게 분리되고 값이 나온다. 페이지와 다르게 움직이는 요소는 "재현 불가" 목록에 잡힌다.
4. 보고서의 코드 조각을 SSGOI 데모에 붙여 넣고 원본과 나란히 재생했을 때 육안으로 구분이
   어렵다.

## 7. 범위 밖

- 웹 UI, 실시간 미리보기, 에디터. (코어를 순수 로직으로 두는 것으로 대비만 한다.)
- 페이지와 따로 움직이는 개별 요소의 값 맞추기. 목록으로 보고만 한다.
- blur 강도 곡선, 3D/원근 변환. (blur는 후속.)
- SSGOI 프리셋 기본값이나 시맨틱 프리셋 값을 도구가 직접 고치는 것. 도구는 값을 제안하고,
  반영은 사람이 한다.

## 8. 참고 사실

- SSGOI 물리값 단위: mass 1, 변위 0→1 정규화. spring `{ stiffness, damping, doubleSpring? }`,
  inertia `{ acceleration, resistance }`(quadratic 저항). 시뮬레이션은 60 fps 고정 스텝,
  50 ms 연속 정착이면 종료.
- Apple duration/bounce 변환: `stiffness = (2π/D)²`, `damping = 4π(1−bounce)/D` (bounce ≥ 0),
  `damping = 4π/(D(1+bounce))` (bounce < 0). SwiftUI 기본은 smooth 0 / snappy 0.15 / bouncy 0.3.
- SSGOI 시맨틱 프리셋 초기값(추정치, 이 도구로 보정 예정): smooth 0.40 s/0, snappy 0.30 s/0.15,
  bouncy 0.45 s/0.30, gentle 0.55 s/0, swift 0.20 s/0, accelerate 0.20 s 도달 inertia.
- iPhone 화면 녹화 기본 코덱은 HEVC, 최근 기기는 60 fps.
