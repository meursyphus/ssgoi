Web pages don't transition — they swap. You click a link, the old page vanishes, the new one appears. Native apps don't do that: they slide, drill, and fade between screens. This guide shows how to get that feel in the **Next.js App Router**, cross-browser and SSR-safe, in two steps.

We'll use [SSGOI](/), a router-agnostic transition engine built on the Web Animations API.

## Why not just the View Transition API?

The native View Transition API is great, but in 2026 its **cross-document (multi-page) support is still limited outside Chromium**, it has no spring physics, and you don't control enter/exit independently. SSGOI fills those gaps: it works in every modern browser, preserves back/forward state, and is driven by spring physics pre-computed into Web Animations API keyframes for 60fps off the main thread.

## Step 1 — Wrap your app once

Install the package:

```bash
npm install @ssgoi/react
```

Then wrap your app in the root layout. This is the only Client Component you need to add — your pages can remain Server Components.

```tsx
// app/layout.tsx
"use client";

import { Ssgoi } from "@ssgoi/react";
import { drill, fade } from "@ssgoi/react/view-transitions";

const config = {
  transitions: [
    // iOS-style drill-in when entering a post, ease back out
    drill({ enter: "/post/*", exit: "*" }),
    // Calm cross-fade between top-level pages
    fade({ paths: ["/", "/about"] }),
  ],
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>
        <Ssgoi config={config}>
          {/* relative + z-0: the outgoing page is cloned with position:absolute */}
          <div className="relative z-0 min-h-dvh overflow-x-clip">
            {children}
          </div>
        </Ssgoi>
      </body>
    </html>
  );
}
```

The wrapper needs `relative z-0` (and `overflow-x-clip` for horizontal transitions) because SSGOI clones the leaving page with `position: absolute` so it can animate out while the new page mounts in.

## Step 2 — Mark your pages

Add a `data-ssgoi-transition` attribute to each page's root element. The value is the path key your config matches against.

```tsx
// app/page.tsx
export default function HomePage() {
  return (
    <main data-ssgoi-transition="/">
      <h1>Home</h1>
    </main>
  );
}

// app/post/[id]/page.tsx
export default function PostPage({ params }: { params: { id: string } }) {
  return (
    <main data-ssgoi-transition={`/post/${params.id}`}>
      <h1>Post Detail</h1>
    </main>
  );
}
```

That's it. Navigations now drill in and ease back out like a native app.

## Choosing a transition

Each transition is a factory you drop into `config.transitions`:

| Transition | Feel | Config shape |
| ---------- | ---- | ------------ |
| `fade` | calm cross-fade, safe default | `fade({ paths })` |
| `drill` | iOS list → detail | `drill({ enter, exit })` |
| `hero` | shared element morph | `hero({ paths })` |
| `sheet` | bottom sheet | `sheet({ enter, exit })` |
| `slide` | horizontal tabs | `slide({ paths })` |

See all the transitions live on the [demos](/), or read the [docs](/docs).
