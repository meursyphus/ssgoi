# Demo

ssgoi 트랜지션을 "진짜 앱처럼" 보이게 하기 위한 쇼케이스 화면들.
실제 백엔드는 없고, 모든 데이터는 각 도메인 폴더 안에 정의된 mock으로 동작한다.

라우트(`src/app/demo/*`)는 얇은 쉘 역할만 하고, 화면 컴포넌트 / 상태 / 데이터 정의는 모두 `src/demo/{showcase}/` 안에 둔다.

## 구조
```
demo/
  {showcase}/         ← air-bnb, instagram 등 쇼케이스 1개 단위
    api/{domain}/     ← 모킹 server action (폴더 내 mock 데이터 사용)
    state/{domain}/   ← 상태 관리 (comwit)
    page/{route}/     ← 화면 컴포넌트
      layout/         ← 쇼케이스별 레이아웃 (모바일/데스크탑 셸 등)
```

`src/app/demo/{showcase}/{route}/page.tsx`는 위 `page/{route}/`에서 컴포넌트 하나만 import해서 렌더링한다.

## 규칙
- 쇼케이스 간 크로스 import 금지 (`air-bnb` → `instagram` 금지)
- 공용은 `src/lib/` (UI / 유틸 / StateProvider 래퍼 / MobileFrame 같은 공통 목업)
- 의존 흐름: `page → state → api`
- 개발 순서: api → state → page (바텀업)
- **Provider는 쇼케이스 Layout에서 직접 건다**: `demo/{showcase}/page/layout/client.tsx` 에서 `StateProvider`(ComwitProvider 래퍼) + `OverlayProvider` + `Toaster` + `Ssgoi` config + 모바일/데스크탑 셸을 모두 둘러싼다.
- 루트 `src/app/layout.tsx`는 글로벌 스타일/폰트 정도만 처리. 쇼케이스 전용 provider는 루트에 올리지 않는다 (쇼케이스마다 독립).

## Import Rules
- **외부에서는 반드시 index.ts 통해서만 import**
  - 예: `import { RoomAPI } from '@/demo/air-bnb/api/room'`
  - 금지: `import { findAll } from '@/demo/air-bnb/api/room/actions/find-all'`
  - 금지: `import type { Room } from '@/demo/air-bnb/api/room/types'`
- 같은 domain 폴더 내에서는 relative import 허용
- api는 주로 state에서 호출한다. 서버 컴포넌트에서 직접 호출해 `silent()` init에 쓰는 경우도 있으나, **클라이언트 컴포넌트에서 useEffect로 api를 직접 호출하는 것은 금지**
