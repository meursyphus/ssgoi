# SSGOI framework and router guides

Choose the guide that owns the application's routed DOM lifecycle. Each guide
is self-contained from install through the first working boundary.

Main setup and route-rule overview: https://ssgoi.dev/llms.txt

React Native / Expo Router experimental integration (separate native lifecycle and a
limited preset set): https://ssgoi.dev/llms/frameworks/expo.txt

Shell class strings in these guides are Tailwind shorthand. Without Tailwind,
apply `position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`.
Use `clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Router integrations

Import SsgoiRouteBoundary from the entry for your installed router:

- Next.js App Router: `@ssgoi/nextjs`
- React Router 6/7: `@ssgoi/react-router`
- TanStack Router 1: `@ssgoi/tanstack-router`
- SvelteKit 2 / Svelte 5: `@ssgoi/svelte/sveltekit`
- Nuxt / Vue Router 4: `@ssgoi/vue/nuxt` or `@ssgoi/vue/vue-router`
- SolidStart / Solid Router 0.15–0.16: `@ssgoi/solid/solidstart`
- Expo Router 56.2 (experimental): `@ssgoi/expo-router`

The Next.js, React Router, TanStack Router, and Expo Router entries above are
separate packages. Install the one for your application; each re-exports the
common platform API and adds its boundary. Host routers are required peers with
supported versions. Platform packages remain independent of those routers.

SvelteKit, Nuxt, Vue Router, and SolidStart currently remain optional subpaths
of their platform packages. Those routers are excluded from root exports and
are optional peers, so plain platform imports do not require a router.

Manual/custom-router boundaries: https://ssgoi.dev/llms/manual-boundaries.txt
Qwik and Angular keep their page-root markers rather than a wrapper component.

The remaining optional subpaths use broad peer ranges because package managers
cannot scope them to a subpath. The separate router packages instead declare
their supported ranges directly. Older or custom routers can use the platform
package and manual boundaries.
