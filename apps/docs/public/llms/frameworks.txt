# SSGOI framework guides

Choose your rendering framework first. Each package supplies a common implementation;
routers connect through a `framework` object on the provider that reads the router,
so there is no router package or subpath to install.
Next.js is the only router integration not marked experimental.

## Router integration

Pass `framework` to the provider and use the layout boundary from the
binding's root entry. The framework returns a route object (at least
`{ pathname }`). The boundary throws if its provider has no `framework`. Each
guide has the copy-pasteable object.

Layout boundaries take no SSGOI props. Each sets two values: `key` is when the
DOM is replaced (its lifetime), and `id` is which route SSGOI matches
transition rules against. The id is always the route path. The key comes from
`config.layouts`, a tree of `{ paths, except?, layouts? }` scopes: a boundary
at depth N (the number of boundaries above it) keys by the scope instance that
matches at depth N, and by the route path when none does. Siblings are
first-match, and a `*` or `:id` segment makes each captured value its own
instance. Without `layouts`, every boundary keys by the route path.
Full patterns: https://ssgoi.dev/llms/complex-routing.txt

| Framework | Router | `framework` | Boundary | Status |
| --- | --- | --- | --- | --- |
| React | Next.js | `useRoute` returning `{ pathname, renderedPath }` from `usePathname` + `useSelectedLayoutSegments` | `SsgoiLayoutBoundary` | Next.js App Router |
| React | Remix | `{ useRoute: () => useLocation() }` | `SsgoiLayoutBoundary` | Experimental |
| React | React Router | `{ useRoute: () => useLocation() }` | `SsgoiLayoutBoundary` | Experimental |
| React | TanStack Router | `useRoute` from the rendered leaf match | `SsgoiLayoutBoundary` | Experimental |
| Svelte | SvelteKit | `{ getRoute: () => ({ pathname: page.url.pathname }), onNavigate }` | `SsgoiLayoutBoundary` | Experimental |
| Vue | Vue Router | `{ getRoute: () => ({ pathname: router.currentRoute.value.path }) }` | `SsgoiLayoutBoundary` | Experimental |
| Vue | Nuxt | `{ getRoute: () => ({ pathname: router.currentRoute.value.path }) }` | `SsgoiLayoutBoundary` | Experimental |
| Solid | Solid Router | `{ getRoute: () => ({ pathname: location.pathname }) }` | `SsgoiLayoutBoundary` | Experimental |
| Solid | SolidStart | `{ getRoute: () => ({ pathname: location.pathname }) }` | `SsgoiLayoutBoundary` | Experimental |
| Qwik | Qwik City | `{ location: useLocation() }` | `useSsgoiLayoutBoundary` | Experimental |
| Angular | Angular Router | `getRoute(injector)` + `onNavigate(injector, callback)` | `*ssgoiLayoutBoundary` | Experimental |
| React Native | Expo Router | `{ StackRouter, unstable_integrateWithRouter }` | `SsgoiLayoutBoundary` | Experimental |

Qwik's hook returns an id and key so the page retains ownership of its DOM and
projected slots. Angular binds the framework on the provider element
(`<main ssgoi [config]="config" [ssgoiFramework]="framework">`) and marks pages
with the `*ssgoiLayoutBoundary` structural directive. Expo's boundary is a native file-based navigator; web presets
and DOM attributes do not apply.

The older router subpaths (`@ssgoi/react/nextjs`, `@ssgoi/svelte/sveltekit`,
`@ssgoi/vue/nuxt`, ...) and their `SsgoiRouteBoundary` still work but are
deprecated and will be removed in 8.0.0.

Root entries never import a router; your `framework` object does the reading.
Check each guide for the tested versions. Remix 2 follows its own React 18
requirements.
