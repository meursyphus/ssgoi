# SSGOI - How it works (for debugging)

Deep-dive companion: https://ssgoi.dev/llms.txt

Read this when a transition misbehaves and you need the underlying mechanism.

When a route changes, SSGOI coordinates two sides. A preset may overlap them,
run them in parallel, or sequence them:

- **OUT**: The leaving page animates out
- **IN**: The entering page animates in

## Core mechanism: unmount, reinsert, and absolute position

In React, a route-boundary key change removes the old DOM subtree and mounts a
new one. SSGOI observes the marked boundary, preserves the detached outgoing
node, and temporarily reinserts that same node with `position: absolute`. The
OUT page can then animate while the IN page occupies normal layout flow.

```ts
// Internal behavior (packages/core/src/lib/utils/prepare-outgoing.ts)
export const prepareOutgoing = (element, context) => {
  element.style.position = "absolute"; // Removed from flow
  element.style.width = "100%";
  element.style.top = `${-1 * (context?.scrollOffset?.y ?? 0)}px`;
  element.style.left = "0";
};
```

**Why this matters:**

- The OUT page is the detached real DOM node, reinserted with
  `position: absolute`
- It needs a positioned ancestor (`relative`) to stay in place
- Without proper CSS setup, the OUT page will jump to the wrong position

## Transition flow

```
/home -> /about navigation:

1. User clicks link to /about
2. The boundary key changes, so React unmounts /home
3. SSGOI preserves that detached node and reinserts it with position: absolute (OUT)
4. React renders /about page (IN)
5. The preset coordinates the OUT and IN phases in parallel or sequence
6. Animation complete, the reinserted /home node is removed from DOM
```

`data-ssgoi-transition` supplies the logical route id used to pair OUT and IN
and match transition config. SSGOI observes the lifecycle; it does not navigate
or change React keys. The deprecated React `<SsgoiTransition>` component only
rendered this attribute, so applications should set it directly on their keyed
route boundary.

## Nested boundary ownership

Persistent layouts may contain another route boundary. SSGOI resolves changed
DOM hierarchically:

- If a parent and descendant enter or leave in the same mutation, the parent
  owns that transition. Descendants are registered or cleaned up silently.
- If the parent remains mounted and only the child changes, the child owns the
  transition.

This lets one provider handle sliding tab content while a bottom navigation
remains still, then animate the full shell when its route group exits:
https://ssgoi.dev/llms/complex-routing.txt
