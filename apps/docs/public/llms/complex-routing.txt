# SSGOI complex routing and persistent layouts

Start with `SsgoiRouteBoundary` from `@ssgoi/react/nextjs`. Keep one `<Ssgoi>`
and config. Add boundaries only where routed DOM lifetimes differ.

- `id` is the route matched by SSGOI rules.
- `key` controls DOM lifetime; omitted key defaults to id.
- `routeKey` overrides the resolved key for a layout-owned persistent shell.
- `resolve` runs synchronously with routed children. Do not defer keys to effects.

## 1. Persistent header or bottom navigation

If a route layout already owns a whole section, no resolver is needed:

```tsx
// app/products/layout.tsx
import type { ReactNode } from "react";
import { SsgoiRouteBoundary } from "@ssgoi/react/nextjs";
import { ProductHeaderAndTabs } from "./product-header-and-tabs";

export default function ProductsLayout({ children }: { children: ReactNode }) {
  return (
    <SsgoiRouteBoundary routeKey="products-layout">
      <ProductHeaderAndTabs />
      <SsgoiRouteBoundary>{children}</SsgoiRouteBoundary>
    </SsgoiRouteBoundary>
  );
}
```

The outer marker keeps the current pathname while its key stays stable. Child
navigation animates only the inner content. The section layout unmounts when
leaving /products; a changed ancestor boundary must not wrap this whole section
on each child navigation. Put one provider above all sections and boundaries
at the route layouts that own them.

When outer and inner boundaries leave together, the outer one owns the motion.
The child animates only while its parent stays mounted.

## 2. Tabs, dynamic projects, and intercepted backgrounds

For an app-shell shared across tabs, details, and projects, define the policy
once in a client component. The adapter already reads Next's hooks and handles
Suspense. There is no local hook/lifecycle implementation to copy.

Example tree (route groups do not appear in URLs):

```text
app/(app)/layout.tsx                     # one provider + AppBoundary
app/(app)/(tabs)/layout.tsx              # TabContent + BottomNav + @modal
app/(app)/(tabs)/projects/page.tsx       # /projects
app/(app)/(tabs)/profile/page.tsx        # /profile
app/(app)/(tabs)/@modal/default.tsx      # returns null
app/(app)/(tabs)/@modal/(.)p/[id]/page.tsx
app/(app)/(detail)/p/[id]/page.tsx       # direct /p/:id
app/(app)/(detail)/projects/[id]/layout.tsx  # project header + child boundary
```

```tsx
// app/app-boundaries.tsx
"use client";

import type { ReactNode } from "react";
import {
  SsgoiRouteBoundary,
  selectedSegmentsToPath,
  type NextjsRouteLocation,
} from "@ssgoi/react/nextjs";

function resolveApp({ selectedSegments }: NextjsRouteLocation) {
  // This boundary is at a URL-root layout. [] means its actual index route,
  // even when the browser URL points at an intercepted modal.
  const id = selectedSegmentsToPath(selectedSegments);
  const key = selectedSegments.includes("(tabs)")
    ? "app-tabs"
    : id.match(/^\/projects\/[^/]+/)?.[0] ?? id;
  return { id, key };
}

export function AppBoundary({ children }: { children: ReactNode }) {
  return <SsgoiRouteBoundary resolve={resolveApp}>{children}</SsgoiRouteBoundary>;
}

export function TabContent({ children }: { children: ReactNode }) {
  return (
    <SsgoiRouteBoundary
      resolve={({ selectedSegments }) => ({
        id: selectedSegmentsToPath(selectedSegments),
      })}
    >
      {children}
    </SsgoiRouteBoundary>
  );
}
```

Render `<TabContent>{children}</TabContent>`, `<BottomNav />`, and `{modal}` as
siblings in the tabs layout. The modal goes outside the background boundary.
`usePathname()` follows the modal URL; `selectedSegments` follows the owned
slot. Thus a soft modal leaves the background DOM/state intact, while a direct
entry resolves the full-page detail. `parallelRoutesKey="modal"` reads a named
slot instead of `children` when that is the region you own.

For a nested project layout, pass its known base path:
`selectedSegmentsToPath(selectedSegments, "/projects/" + projectId)`.
The helper strips route groups and interception prefixes, and keeps catch-all
segments. It joins segments under the base you provide; it is not a general
resolver for the relative ancestry of `( .. )` interception destinations.
For a modal destination, use a canonical id from the route's params if needed.

A project child boundary belongs around only its changing content. The outer
project key stays `/projects/:id`; inner tabs can animate independently.
If child transitions are not wanted, omit that inner boundary.

## 3. Middleware / proxy remains app configuration

Next.js route interception is provided by your route/slot tree. SSGOI does not
create intercepting routes, rewrite URLs, or configure request middleware.
Ordinary App Router transitions need no extra middleware.

If your application uses `middleware.ts` (Next 13–15) or `proxy.ts` (Next 16+),
review its matcher and redirect/rewrite behavior for intercepted routes too:

- Preserve intended soft navigation and RSC/prefetch requests. A redirect can
  change the destination or turn the intended flow into a full navigation.
- When changing forwarded request headers, start with the existing headers
  (`new Headers(request.headers)`) so Next's routing headers survive.
- Keep direct-entry URLs valid, provide the parallel slot's `default.tsx` and
  close/fallback routes, and retain server authorization checks.
- Rewrites can make SSR and browser pathnames differ. Resolve a stable slot id
  where possible; follow Next's stable-fallback hydration pattern for custom
  wrappers. Suspense alone does not normalize rewritten paths.

There is no universal rewrite to paste: rules depend on the application's
routing and auth design. This is also separate from SSGOI's animation
`middleware` config, which handles transition pairs and scroll behavior.

Verify: click opens the modal; close/back restores the same background state;
reload/direct entry renders the full detail; tab changes preserve BottomNav;
project-child changes preserve the project header. Test these with the app's
actual proxy/middleware enabled.
