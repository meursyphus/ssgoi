# SSGOI complex routing and persistent layouts

Start from https://ssgoi.dev/llms/frameworks/nextjs.txt: one `<Ssgoi>`, one
config, and the Next.js `framework` whose `useRoute` returns
`{ pathname, renderedPath }`. Boundaries take no SSGOI props. You describe
which routes share a layout in `config.layouts`, and place one
`<SsgoiLayoutBoundary>` in each layout that owns a lifetime.

- `id` (`data-ssgoi-transition`) is the route path; route rules match it.
- `key` decides when the DOM is replaced. A boundary at depth N keys by the
  `config.layouts` scope instance that matches at depth N, or by the route path
  when no scope matches there.
- Depth is automatic: no boundary above → depth 0; inside one → one deeper.
- Without `layouts`, every boundary keys by the route path.

## 1. `config.layouts`

```ts
// SsgoiLayoutScope, from "@ssgoi/react"
type SsgoiLayoutScope = {
  paths: string | string[];      // route-rule patterns: /x, /x/*, /x/**, /x/:id
  except?: string | string[];
  layouts?: SsgoiLayoutScope[];  // the next depth inside this scope
};
```

- Siblings in one array are tried in order; the first scope whose `paths`
  match (and whose `except` does not) is chosen. Put narrow scopes first.
- `layouts` lists the child scopes for the next depth.
- A `*` or `:id` segment makes each captured value its own instance:
  `/projects/:id/**` gives `/projects/1/files` and `/projects/1/members` one
  shared shell, and `/projects/2` another. A `**` tail is not captured.

## 2. Tabs with a bottom nav, details, and a nested section

This is the layout of the Next.js template
(https://github.com/meursyphus/ssgoi/tree/HEAD/templates/nextjs):

```text
app/
├─ layout.tsx                      <Ssgoi> + boundary               depth 0
├─ (top-level)/layout.tsx          boundary + <BottomNav /> outside depth 1
│  ├─ posts/page.tsx               /posts
│  ├─ pinterest/page.tsx           /pinterest
│  ├─ profile/page.tsx             /profile
│  └─ products/layout.tsx          header + category tabs + boundary depth 2
│     └─ all/, electronics/, ...   /products/all, /products/electronics
└─ (detail)/layout.tsx             boundary                         depth 1
   └─ posts/[id], pinterest/[id], profile/[id]
```

```ts
import { drill, fade, slide, zoom } from "@ssgoi/react/view-transitions";

const CATEGORIES = ["all", "electronics", "fashion", "home", "beauty"];

// Bottom-nav tabs, including every product category.
const TOP_LEVEL = ["/posts", "/products/**", "/pinterest", "/profile"];

const config = {
  layouts: [
    // depth 0: one shell for the tabs; depth 1: the products section inside it
    { paths: TOP_LEVEL, layouts: [{ paths: "/products/**" }] },
    // depth 0: one shell for every detail page
    { paths: "/**", except: TOP_LEVEL },
  ],
  transitions: [
    { from: "/pinterest", to: "/pinterest/*", transition: zoom({ type: "expand" }) },
    { on: "/posts/**", except: "/posts", transition: drill() },
    { from: "/profile", to: "/profile/*", transition: zoom({ type: "static" }) },
    { ordered: CATEGORIES.map((id) => `/products/${id}`), transition: slide() },
    { from: TOP_LEVEL, to: TOP_LEVEL, transition: fade() },
  ],
};
```

Use `/products/**`, not `/products/*`: a `*` captures, so each category would
become its own scope instance and the category tabs would remount.

```tsx
// app/(top-level)/layout.tsx
import type { ReactNode } from "react";
import { SsgoiLayoutBoundary } from "@ssgoi/react";
import { BottomNav } from "@/components/bottom-nav";

export default function TopLevelLayout({ children }: { children: ReactNode }) {
  return (
    <div className="flex flex-1 flex-col">
      <SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
      <BottomNav />
    </div>
  );
}

// app/(top-level)/products/layout.tsx: header + category tabs + <SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
// app/(detail)/layout.tsx: <SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
```

| Navigation | depth 0 | depth 1 | depth 2 | Result |
| --- | --- | --- | --- | --- |
| tab → tab | same | changes | — | only tab content fades; BottomNav stays |
| category → category | same | same | changes | category content slides; header and tabs stay |
| tab → detail | changes | — | — | the whole tab shell leaves, BottomNav included |
| detail → detail | same | changes | — | detail content swaps |

When an outer and an inner boundary leave in the same navigation, the outer
one owns the motion and the inner one goes with it. Keep persistent UI inside
the boundary that should take it away, and outside the one that changes.

## 3. Intercepted modals and parallel slots

During a soft intercept the URL becomes the modal's (`/p/42`) while the
`children` slot still renders the background. The Next.js `useRoute` returns
`renderedPath` from `useSelectedLayoutSegments()` at the provider, with route
groups and interception markers removed, so every boundary keeps following the
background and nothing behind the modal moves. Render the `{modal}` slot
outside the boundaries; it animates by itself. Direct entry to `/p/42` renders
the full page, whose rendered path is `/p/42`.

```tsx
// app/(top-level)/layout.tsx with an @modal slot
export default function TopLevelLayout({ children, modal }: { children: ReactNode; modal: ReactNode }) {
  return (
    <>
      <SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
      <BottomNav />
      {modal}
    </>
  );
}
```

For a per-instance shell such as a project workspace, capture the id:

```ts
layouts: [
  { paths: ["/projects", "/profile"] },   // top-level tabs
  { paths: "/projects/:id/**" },          // one instance per project
]
```

Everything under `/projects/acme` shares one depth-0 instance, so the project
header survives while the id keeps following the full route. Leave a project
child without a boundary when overview → docs should be a plain swap.

## 4. Middleware / proxy remains app configuration

Next.js route interception is provided by your route/slot tree. SSGOI does not
create intercepting routes, rewrite URLs, or configure request middleware.
Ordinary App Router transitions need no extra middleware.

If your application uses `middleware.ts` (Next 13–15) or `proxy.ts` (Next 16+),
review its matcher and redirect/rewrite behavior for intercepted routes too:

- Preserve intended soft navigation and RSC/prefetch requests. A redirect can
  change the destination or turn the intended flow into a full navigation.
- When changing forwarded request headers, start with the existing headers
  (`new Headers(request.headers)`) so Next's routing headers survive.
- Keep direct-entry URLs valid, provide the parallel slot's `default.tsx` and
  close/fallback routes, and retain server authorization checks.
- Rewrites can make SSR and browser pathnames differ. Prefer the rendered path
  from the selected segments; follow Next's stable-fallback hydration pattern
  for custom wrappers. Suspense alone does not normalize rewritten paths.

There is no universal rewrite to paste: rules depend on the application's
routing and auth design. This is also separate from SSGOI's animation
`middleware` config, which handles transition pairs and scroll behavior.

Verify: click opens the modal; close/back restores the same background state;
reload/direct entry renders the full detail; tab changes preserve BottomNav;
project-child changes preserve the project header. Test these with the app's
actual proxy/middleware enabled.
