# SSGOI scroll restoration and middleware

SSGOI derives scroll reset and restoration from the matched route rule. Most
applications should keep this automatic policy.

Main setup: https://ssgoi.dev/llms.txt

## Scrolling during a transition

SSGOI suppresses accidental wheel, single-finger touchmove, and page-scroll key
input by default in the automatically detected scroll container. The listeners
run from transition preparation until the outgoing page has been removed or
hidden, preventing ordinary scroll input from exposing blank space below a short
incoming page while a tall outgoing page is still present.

The lock does not read or change CSS, scrollbar visibility, gutter, padding, or
container dimensions. Native scrollbar clicking/dragging and programmatic
scrolling remain available. It does not rewind native momentum that was already
running when the transition started. Text editing, button activation and zoom
gestures retain their normal behavior. Overlapping transitions share ownership
of the input listeners.

Set `scrollLock: false` on the top-level web config if your application manages
scroll locking itself:

```ts
const config = {
  scrollLock: false,
  transitions: [{ from: "/gallery", to: "/photo/*", transition: zoom() }],
};
```

The option does not change `preserveScroll`. A navigation with no matching
transition, and a native swipe-back handled by the browser, acquire no lock.
Completion, interruption, preparation errors and provider teardown release it.
Async preparation has a 5-second deadline; paused animation playback does not.

## Automatic policy

| rule | forward `from` side | forward `to` side |
| --- | --- | --- |
| `on` (scope entry / leave) | restore | reset |
| `from` / `to` | restore | reset |
| `ordered` | restore | restore |

The outgoing page always keeps its current scroll during its OUT animation.
Reset or restoration runs only when a page becomes IN.

For an `on` rule, paths outside the scope are semantic `from` and paths inside
are semantic `to`. When both paths are already inside the same `on` scope, both
endpoints are semantic `to`, so the default is reset / reset. For stack UX, use
`except` to keep the source route outside the scope. For `ordered`, the
lower-index side is semantic `from` and the higher-index side is semantic `to`.

## Override one rule

Use `preserveScroll` only when the automatic policy is wrong for that
relationship:

```ts
{
  from: "/gallery",
  to: "/photo/*",
  preserveScroll: { from: true, to: true },
  transition: zoom(),
}
```

`from` and `to` always refer to the rule's semantic forward relationship.
Backward navigation reverses their physical OUT/IN roles.

## Middleware

Rewrite route ids before matching, for example to remove locale prefixes:

```ts
const config = {
  middleware: (from, to) => ({
    from: from.replace(/^\/(en|ko)(?=\/|$)/, ""),
    to: to.replace(/^\/(en|ko)(?=\/|$)/, ""),
  }),
  transitions: [
    { on: "/posts/**", except: "/posts", transition: drill() },
  ],
};
```
