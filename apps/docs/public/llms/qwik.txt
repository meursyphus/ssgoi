# SSGOI - Qwik / Qwik City setup

Framework-specific setup for `@ssgoi/qwik`. The `SsgoiConfig` shape, transition catalog, and troubleshooting are shared across frameworks — read https://ssgoi.dev/llms.txt for those.

## Installation

```bash
npm install @ssgoi/qwik
```

Reference template: https://github.com/meursyphus/ssgoi/tree/main/templates/qwik

## Layout setup

Qwik uses resumability and serializes component state, while SSGOI transition configs contain functions. Use `config$` (a QRL factory created with `$(() => config)`) instead of passing a plain `config` object. The Qwik adapter resolves that QRL in the browser task before creating the SSGOI observer.

In Qwik City layouts, prefer `useSsgoi(ref, { config$ })` over wrapping the route `<Slot />` in `<Ssgoi>`. Forwarding a Qwik City route slot through another component prevents routed content from being projected into the live DOM.

```tsx
import { $, Slot, component$, useSignal } from "@builder.io/qwik";
import { useSsgoi } from "@ssgoi/qwik";
import { drill, zoom } from "@ssgoi/qwik/view-transitions";

const config$ = $(() => ({
  preserveScroll: { exclude: ["/post/*"] },
  transitions: [
    { on: "/post/**", except: "/post", transition: drill() },
    {
      from: "/gallery",
      to: "/gallery/*",
      transition: zoom({ type: "expand" }),
    },
  ],
}));

export default component$(() => {
  const ssgoiRoot = useSignal<HTMLElement>();

  useSsgoi(ssgoiRoot, { config$ });

  return (
    <main
      ref={ssgoiRoot}
      class="relative z-0 h-dvh overflow-y-auto overflow-x-clip"
    >
      <Slot />
    </main>
  );
});
```

## Route boundary rule

Each page component marks its own boundary:

```tsx
export default component$(() => {
  return (
    <section data-ssgoi-transition="/gallery">{/* page content */}</section>
  );
});
```

The value can be a hard-coded logical page id; it only needs to match the `on`, `from`, `to`, or `ordered` route patterns in `SsgoiConfig`. For dynamic routes, match with wildcards in the config (`/post/*`).

## Troubleshooting checklist

- The root layout imports `useSsgoi` from `@ssgoi/qwik` and calls it with a signal ref.
- The config is declared with Qwik `$`, for example `const config$ = $(() => ({ transitions: [...] }))`.
- Each page component has its own `data-ssgoi-transition` value that matches an `on`, `from`, `to`, or `ordered` route pattern.
- The SSGOI root element is the scroll/positioning shell (`relative z-0 overflow-x-clip`) and contains the route `<Slot />` directly.
