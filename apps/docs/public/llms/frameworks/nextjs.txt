# SSGOI with React and Next.js

Use one provider, tell it how to read Next.js's route through `framework`, and
import `SsgoiLayoutBoundary` from the root `@ssgoi/react` entry. Next.js App
Router 13.4–16 is supported; `@ssgoi/react` never imports `next` itself.

Framework index: https://ssgoi.dev/llms/frameworks.txt

## Install

```bash
npm install @ssgoi/react
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Provider

```tsx
// app/ssgoi-provider.tsx
"use client";

import { type ReactNode } from "react";
import { usePathname, useSelectedLayoutSegments } from "next/navigation";
import { Ssgoi, type SsgoiFramework } from "@ssgoi/react";
import { drill } from "@ssgoi/react/view-transitions";

const config = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};

const framework: SsgoiFramework = {
  useRoute: ({ parallelRoutesKey = "children" }) => {
    const pathname = usePathname();
    const selectedSegments = useSelectedLayoutSegments(parallelRoutesKey) ?? [];
    return pathname == null ? null : { pathname, selectedSegments };
  },
};

export function SsgoiProvider({ children }: { children: ReactNode }) {
  return (
    <Ssgoi config={config} framework={framework}>
      {children}
    </Ssgoi>
  );
}
```

Keep `config` and `framework` at module scope so both stay stable. The
provider file is a client component, so passing a function is fine.
`useRoute` is a hook the boundary calls on every render; return the current
route, or `null` while the router is not ready.

## Layout boundary

No local component is needed. `SsgoiLayoutBoundary` calls
`framework.useRoute({ parallelRoutesKey })`, which above reads the pathname and
the selected `children` slot. It includes Suspense for Cache Components and
accepts `fallback` (default `null`) while URL data is unresolved. Because
`useRoute` returns `null` when the pathname is null in a mixed app/pages
project, it never registers a guessed route. It targets App Router; use the
manual guide for Pages Router.

It throws an `SSGOI:` error if the nearest `<Ssgoi>` has no `framework`.

```tsx
import { SsgoiLayoutBoundary } from "@ssgoi/react";

<SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
```

## Layout

```tsx
// app/layout.tsx
import { type ReactNode } from "react";
import { SsgoiLayoutBoundary } from "@ssgoi/react";
import { SsgoiProvider } from "./ssgoi-provider";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <main className="relative z-0 min-h-dvh overflow-x-clip">
          <SsgoiProvider>
            <SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
          </SsgoiProvider>
        </main>
      </body>
    </html>
  );
}
```

## Boundary options

- `as`: wrapper element or React component; defaults to `div`. Custom components
  must forward DOM attributes to their root.
- DOM attributes (`id`, `className`, `style`, events, `aria-*`, `data-*`) pass through.
  HTML `id` is not the transition id. The boundary owns `data-ssgoi-transition`.
- `boundary`: the boundary's key (when its DOM is replaced) and id (which route
  SSGOI matches rules against). Defaults: id = pathname, key = id. Pass a
  string (a fixed key, e.g. `boundary="products-layout"` for a persistent
  layout), `{ id?, key? }`, or `(route) => string | { id?, key? }`. The function
  form receives the object `useRoute` returned, here
  `{ pathname, selectedSegments }`, as-is; a returned string is the key.
  Annotate its parameter, e.g.
  `({ selectedSegments }: { pathname: string; selectedSegments: string[] })`.
  It runs synchronously with the routed children. Do not set React `key` on
  the boundary.
- `parallelRoutesKey`: passed to `useRoute`; above, the slot name without `@`,
  default `children`.
- `fallback`: Suspense and unresolved-path fallback, default `null`. Prefer a
  lightweight placeholder; rendering routed children here can mount them twice.

A persistent products layout can use `boundary="products-layout"` outside its
header/tabs and a default boundary around its children. For dynamic projects,
return `{ id: pathname, key: "/projects/:id" }` from the function form. A
function `boundary` must be defined in a client component; string and object
forms can be passed from a server layout.

## Interception and middleware / proxy

The component manages DOM lifetime. Your application still owns intercepted
route files, parallel slots, and any middleware/proxy redirects or rewrites.
Middleware is called `middleware.ts` in Next 13–15 and `proxy.ts` in Next 16+.
No SSGOI middleware is required for ordinary App Router navigation.

If you already rewrite or redirect, review the matcher and rules for both
client navigation (including RSC/prefetch requests) and direct entry. Avoid
turning an intended soft interception into a redirect/full document load. When
forwarding request headers, retain the existing headers instead of rebuilding
them from only application headers. Keep authorization checks on the server.
Do not install a generic interception rewrite: it depends on your route tree.

For `@modal`, compute `boundary` from `selectedSegments` so opening the modal does
not remount the background using its URL. Add `default.tsx`/slot fallback routes
as required by Next.js. Verify click → modal, close/back → unchanged background,
and reload/direct URL → full page. See the focused example:
https://ssgoi.dev/llms/complex-routing.txt

Rewrites can make server and browser pathnames differ. Suspense alone does not
fix rewrite hydration mismatches. Scope the boundary to a stable owned slot
when possible, or use a custom wrapper with a stable server fallback as in
Next.js's rewrite guidance; do not defer every navigation key to an effect.
