# SSGOI with Solid Router

Experimental API: this router integration may change.

Install @ssgoi/solid in an existing Solid Router application.
Return Solid Router's location pathname from `framework.getRoute` on the common provider. SolidStart uses this same setup.

Keep one common provider above the following boundary.

## Wrap the routed children

Render the provider inside <Router> so useLocation works. The keyed boundary recreates the changing region while a fixed boundary key can preserve an outer shell. SsgoiLayoutBoundary throws if <Ssgoi> has no framework.

```tsx
import { Router, useLocation, type RouteSectionProps } from "@solidjs/router";
import { Ssgoi, SsgoiLayoutBoundary } from "@ssgoi/solid";
import { config } from "./ssgoi-config";

function Root(props: RouteSectionProps) {
  const location = useLocation();
  return (
    <Ssgoi config={config} framework={{ getRoute: () => ({ pathname: location.pathname }) }}>
      <SsgoiLayoutBoundary>{props.children}</SsgoiLayoutBoundary>
    </Ssgoi>
  );
}

<Router root={Root}>{/* routes */}</Router>
```

## Route lifetime

The default key follows the pathname. The function form of boundary receives the route getRoute returned, as-is, and can return separate id and key values; use a stable shell key only around content that should remain mounted.

SsgoiRouteBoundary from @ssgoi/solid/solid-router still works but is deprecated and will be removed in 8.0.0.
