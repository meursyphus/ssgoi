# SSGOI with TanStack Router

Experimental API: the router integration may change.

TanStack Router wiring. Choose effects from:
https://ssgoi.dev/llms/transitions.txt

```bash
npm install @ssgoi/react
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Setup

Config:

```ts
// app/components/ssgoi-config.ts
import { drill } from "@ssgoi/react/view-transitions";

export const config = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};
```

Everything wires in the root route — one `<Ssgoi>` whose `framework.useRoute`
reads TanStack's router state, the shell classes, and the boundary around
`<Outlet />`:

```tsx
// app/routes/__root.tsx
import { createRootRoute, Outlet, useRouterState } from "@tanstack/react-router";
import {
  Ssgoi,
  SsgoiLayoutBoundary,
  type SsgoiFramework,
} from "@ssgoi/react";
import { config } from "~/components/ssgoi-config";

// Key by the leaf match the outlet renders, not location: location moves
// before pending matches render, and index routes match "/parent/".
const framework: SsgoiFramework = {
  useRoute: () => ({
    pathname: useRouterState({
      select: (state) => {
        const location = state.location.pathname;
        const leaf = state.matches.at(-1)?.pathname;
        if (!leaf) return location;
        return leaf.length > 1 && leaf.endsWith("/") && !location.endsWith("/")
          ? leaf.slice(0, -1)
          : leaf;
      },
    }),
  }),
};

export const Route = createRootRoute({
  component: () => (
    <main className="relative z-0 min-h-dvh overflow-x-clip">
      <Ssgoi config={config} framework={framework}>
        <SsgoiLayoutBoundary>
          <Outlet />
        </SsgoiLayoutBoundary>
      </Ssgoi>
    </main>
  ),
});
```

The selector picks the path of the match the outlet is rendering, not
`location`, which TanStack moves before pending matches render. The
boundary uses that pathname as both its React key and transition id. No local
boundary component is needed. Keep `framework` at module scope;
`SsgoiLayoutBoundary` throws if `<Ssgoi>` has no `framework`.

Verify: navigate `/` → any page slides in from the right; back slides out.

## Beyond the basics

When a section must persist, remove the full-path boundary from the root and
leave only one provider there:

```tsx
<Ssgoi config={config} framework={framework}>
  <Outlet />
</Ssgoi>
```

Give ordinary routes their own pathname boundary. Give the persistent section
a stable outer boundary plus a pathname boundary around its child outlet:

```tsx
// app/routes/products.tsx
<SsgoiLayoutBoundary boundary="products-layout">
  <ProductHeaderAndTabs />
  <SsgoiLayoutBoundary>
    <Outlet />
  </SsgoiLayoutBoundary>
</SsgoiLayoutBoundary>
```

The outer key is fixed; the inner boundary defaults to the pathname. The stable outer key
preserves the shell; the inner pathname key produces child OUT/IN.

- Key-scope reasoning: https://ssgoi.dev/llms/complex-routing.txt
- Full example: https://github.com/meursyphus/ssgoi/tree/HEAD/templates/tanstack-router
- Framework index: https://ssgoi.dev/llms/frameworks.txt

`@ssgoi/react` never imports `@tanstack/react-router`; it calls the `useRoute`
you wrote. `as`, DOM attributes,
and `boundary` (a string key, `{ id?, key? }`, or a function of the route
`useRoute` returned) are supported. Defaults: id = pathname, key = id. Query-only navigation keeps the
boundary by default. For direct control or a custom router:
https://ssgoi.dev/llms/manual-boundaries.txt

`SsgoiRouteBoundary` from `@ssgoi/react/tanstack-router` still works but is
deprecated and will be removed in 8.0.0.
