# SSGOI with SolidStart

Experimental API: the router integration may change.

SolidStart wiring. Choose effects from:
https://ssgoi.dev/llms/transitions.txt

```bash
npm install @ssgoi/solid
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Setup

Everything wires at the router root — one `<Ssgoi>` whose `framework.getRoute`
reads Solid Router's location, the shell classes, and the boundary component around
the routed children:

```tsx
// src/app.tsx
import { Router, useLocation, type RouteSectionProps } from "@solidjs/router";
import { FileRoutes } from "@solidjs/start/router";
import { Suspense } from "solid-js";
import { Ssgoi, SsgoiLayoutBoundary } from "@ssgoi/solid";
import { config } from "./ssgoi-config";

function Root(props: RouteSectionProps) {
  const location = useLocation();
  return (
    <main class="relative z-0 min-h-dvh overflow-x-clip">
      <Ssgoi config={config} framework={{ getRoute: () => ({ pathname: location.pathname }) }}>
        <Suspense>
          <SsgoiLayoutBoundary>{props.children}</SsgoiLayoutBoundary>
        </Suspense>
      </Ssgoi>
    </main>
  );
}

export default function App() {
  return (
    <Router root={Root}>
      <FileRoutes />
    </Router>
  );
}
```

`useLocation` only works inside `<Router>`, so the provider lives in the router
root. `SsgoiLayoutBoundary` throws if `<Ssgoi>` has no `framework`.

```ts
// src/ssgoi-config.ts
import type { SsgoiConfig } from "@ssgoi/solid";
import { drill } from "@ssgoi/solid/view-transitions";

export const config: SsgoiConfig = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};
```

## Beyond the basics

For a persistent `/products` shell, declare it in config and keep the root
boundary as it is:

```ts
export const config = {
  layouts: [{ paths: "/products/**" }],
  transitions: [/* ... */],
};
```

Then add a boundary only around the changing child:

```tsx
// src/routes/products.tsx
<ProductHeaderAndTabs />
<SsgoiLayoutBoundary>
  {props.children}
</SsgoiLayoutBoundary>
```

The root boundary (depth 0) keys every `/products` route by the one scope, so
the shell stays; the inner boundary (depth 1) keys by the path and produces
child OUT/IN.

- Full example: https://github.com/meursyphus/ssgoi/tree/HEAD/templates/solidstart
- Framework index: https://ssgoi.dev/llms/frameworks.txt

Solid Router 0.15–0.16 is supported. The root `@ssgoi/solid` import has no
router dependency; it calls the `getRoute` you pass. The boundary accepts
`as` and DOM attributes and takes no SSGOI props: its id is the route path and
its key is the `config.layouts` scope at its depth (the number of boundaries
above it), or the route path. Query/hash-only changes keep the boundary by
default.

Manual/custom-router guide: https://ssgoi.dev/llms/manual-boundaries.txt

`SsgoiRouteBoundary` from `@ssgoi/solid/solidstart` or
`@ssgoi/solid/solid-router` still works but is deprecated and will be removed
in 8.0.0.
