# SSGOI with Remix

Experimental API: this router integration may change.

Install @ssgoi/react in an existing Remix application.
Use Remix 2 with @remix-run/react. Return Remix's own location from `framework.useRoute`, so SSGOI does not depend on a separately installed React Router version.

Keep one common provider above the following boundary.

## Pass the framework

In root.tsx, give the common provider a useRoute that returns Remix's location. Keep the object at module scope so it stays stable. SsgoiLayoutBoundary throws if <Ssgoi> has no framework.

```tsx
import { Outlet, useLocation } from "@remix-run/react";
import { Ssgoi, type SsgoiFramework } from "@ssgoi/react";
import { config } from "./ssgoi-config";

const framework: SsgoiFramework = { useRoute: () => useLocation() };

export default function App() {
  return (
    <Ssgoi config={config} framework={framework}>
      <Outlet />
    </Ssgoi>
  );
}
```

## Wrap a layout outlet

Place the boundary in a route layout. Follow Remix 2’s own React 18 dependency requirements. React Router 7 framework mode returns React Router’s location instead.

```tsx
import { Outlet } from "@remix-run/react";
import { SsgoiLayoutBoundary } from "@ssgoi/react";

export default function Layout() {
  return <SsgoiLayoutBoundary><Outlet /></SsgoiLayoutBoundary>;
}
```

## Persistent route families

Use a fixed key such as boundary="shell" for a persistent shell and a separate inner boundary for changing content. The function form of boundary receives Remix’s location as useRoute returned it and returns a key string or { id?, key? }; keys are computed during render.

SsgoiRouteBoundary from @ssgoi/react/remix still works but is deprecated and will be removed in 8.0.0.
