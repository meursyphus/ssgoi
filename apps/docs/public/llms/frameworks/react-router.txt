# SSGOI with React Router

React Router framework-mode wiring. Choose effects from:
https://ssgoi.dev/llms/transitions.txt

```bash
npm install @ssgoi/react
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Setup

Config:

```ts
// app/components/ssgoi-config.ts
import { drill } from "@ssgoi/react/view-transitions";

export const config = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};
```

Root — one `<Ssgoi>` + the shell classes:

```tsx
// app/root.tsx — the App component
import { Outlet } from "react-router";
import { Ssgoi } from "@ssgoi/react";
import { config } from "./components/ssgoi-config";

export default function App() {
  return (
    <main className="relative z-0 min-h-dvh overflow-x-clip">
      <Ssgoi config={config}>
        <Outlet />
      </Ssgoi>
    </main>
  );
}
```

Boundary — pathname as both React key and transition id, wired once with a
pathless layout route:

```tsx
import { SsgoiRouteBoundary } from "@ssgoi/react/react-router";
: {
  children: ReactNode;
  name?: BoundaryName;
}) {
  const { pathname } = useLocation();
  const boundary = resolveBoundary(name, pathname);

  return (
    <div key={boundary.key} data-ssgoi-transition={boundary.id}>
      {children}
    </div>
  );
}

// app/routes/page-boundary.layout.tsx
import { Outlet } from "react-router";
import { SsgoiRouteBoundary } from "@ssgoi/react/react-router";

export default function PageBoundaryLayout() {
  return (
    <SsgoiRouteBoundary>
      <Outlet />
    </SsgoiRouteBoundary>
  );
}

// app/routes.ts — wrap your pages with it
import {
  type RouteConfig,
  index,
  layout,
  route,
} from "@react-router/dev/routes";

export default [
  layout("routes/page-boundary.layout.tsx", [
    index("routes/home.tsx"),
    route("posts/:postId", "routes/posts.$postId.tsx"),
  ]),
] satisfies RouteConfig;
```

Verify: navigate `/` → any page slides in from the right; back slides out.

## Beyond the basics

A persistent route family needs two boundaries:

```tsx
// app/routes/products_.layout.tsx
import { Outlet } from "react-router";
import { SsgoiRouteBoundary } from "@ssgoi/react/react-router";

export default function ProductsLayout() {
  return (
    <SsgoiRouteBoundary routeKey="products-layout">
      <ProductHeaderAndTabs />
      <SsgoiRouteBoundary>
        <Outlet />
      </SsgoiRouteBoundary>
    </SsgoiRouteBoundary>
  );
}
```

Mount the products children under this layout, not under the global pathless
`page-boundary` layout. The stable outer key preserves the shell; the inner
pathname key produces child OUT/IN. Holding only one boundary constant
preserves state but produces no child transition.

- Key-scope reasoning: https://ssgoi.dev/llms/complex-routing.txt
- Full example: https://github.com/meursyphus/ssgoi/tree/HEAD/templates/react-router
- Framework index: https://ssgoi.dev/llms/frameworks.txt

The `@ssgoi/react/react-router` subpath uses only its optional router peer.
Root imports and other router entries do not load it. `as`, DOM attributes,
`routeKey`, and `resolve` are supported. Resolve returns `{ id, key? }`; key
defaults to id, and routeKey overrides it. Query-only navigation keeps the
boundary by default. For direct control or a custom router:
https://ssgoi.dev/llms/manual-boundaries.txt

If a React Router 6 app only lists react-router-dom, add the matching version
of react-router as a direct dependency too (especially with strict pnpm layouts).
