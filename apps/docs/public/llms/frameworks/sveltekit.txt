# SSGOI with SvelteKit

Experimental API: the router integration may change.

SvelteKit wiring. Choose effects from:
https://ssgoi.dev/llms/transitions.txt

```bash
npm install @ssgoi/svelte
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Setup

Everything wires in the root layout — one `<Ssgoi>` whose `framework` returns
the current route from SvelteKit's page URL and passes `onNavigate`, the shell
classes, and the boundary component:

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  import { page } from "$app/state";
  import { onNavigate } from "$app/navigation";
  import { Ssgoi, SsgoiLayoutBoundary } from "@ssgoi/svelte";
  import { config } from "$lib/ssgoi-config";

  let { children } = $props();

  const framework = {
    getRoute: () => ({ pathname: page.url.pathname }),
    onNavigate,
  };
</script>

<main class="relative z-0 min-h-dvh overflow-x-clip">
  <Ssgoi {config} {framework}>
    <SsgoiLayoutBoundary class="min-h-full">
      {@render children()}
    </SsgoiLayoutBoundary>
  </Ssgoi>
</main>
```

SvelteKit before 2.12 has no `$app/state`; use the store instead:
`import { page } from "$app/stores"`, `import { get } from "svelte/store"`, and
`getRoute: () => ({ pathname: get(page).url.pathname })`. On navigation the
provider derives the next route from the target URL before Kit swaps the
children. `SsgoiLayoutBoundary` throws if `<Ssgoi>` has no `framework`.

```ts
// src/lib/ssgoi-config.ts
import type { SsgoiConfig } from "@ssgoi/svelte";
import { drill } from "@ssgoi/svelte/view-transitions";

export const config: SsgoiConfig = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};
```

## The boundary component

Why it exists: the root layout wrapper remains mounted while its live children
snippet updates, so a marker on that wrapper has no outgoing node. The
component detaches the old routed region in `onNavigate` first, then remounts
under the new id:

Import `SsgoiLayoutBoundary` from `@ssgoi/svelte`; the package owns this
lifecycle and calls the `onNavigate` you passed. Svelte 5 and SvelteKit 2 are
supported. The root `@ssgoi/svelte` entry never imports Kit.

Verify: navigate `/` → any page slides in from the right; back slides out.

## Beyond the basics

For a persistent `/products` shell, declare it in config and keep the root
boundary as it is:

```ts
export const config = {
  layouts: [{ paths: "/products/**" }],
  transitions: [/* ... */],
};
```

Then add a boundary only around the changing child:

```svelte
<!-- src/routes/products/+layout.svelte -->
<ProductHeaderAndTabs />
<SsgoiLayoutBoundary>
  {@render children()}
</SsgoiLayoutBoundary>
```

The root boundary (depth 0) keys every `/products` route by the one scope, so
the shell stays; the inner boundary (depth 1) keys by the path and produces
child OUT/IN.

- Full example: https://github.com/meursyphus/ssgoi/tree/HEAD/templates/sveltekit
- Framework index: https://ssgoi.dev/llms/frameworks.txt

`as` and HTML attributes pass through; the boundary takes no SSGOI props. Its id
is the pathname and its key is the `config.layouts` scope at its depth, or the
pathname. Search/hash-only changes do not remount. Use router navigation;
shallow `pushState`/`replaceState` calls do not trigger `onNavigate`.

Custom router/manual guide: https://ssgoi.dev/llms/manual-boundaries.txt

`SsgoiRouteBoundary` from `@ssgoi/svelte/sveltekit` still works but is
deprecated and will be removed in 8.0.0.
