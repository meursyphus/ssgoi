# SSGOI with Vue Router and Nuxt

Nuxt wiring comes first; the plain Vue Router variant follows. Choose effects
from:
https://ssgoi.dev/llms/transitions.txt

```bash
npm install @ssgoi/vue
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Setup

Everything wires in the app root — one `<Ssgoi>`, the shell classes, and the
boundary component around `<NuxtPage />`:

```vue
<!-- app.vue -->
<script setup>
import { Ssgoi } from "@ssgoi/vue";
import { SsgoiRouteBoundary } from "@ssgoi/vue/nuxt";
import { config } from "~/utils/ssgoi-config";
</script>

<template>
  <main class="relative z-0 min-h-dvh overflow-x-clip">
    <Ssgoi :config="config">
      <SsgoiRouteBoundary>
        <NuxtPage />
      </SsgoiRouteBoundary>
    </Ssgoi>
  </main>
</template>
```

```ts
// utils/ssgoi-config.ts
import type { SsgoiConfig } from "@ssgoi/vue";
import { drill } from "@ssgoi/vue/view-transitions";

export const config: SsgoiConfig = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};
```

## The boundary component

A changed key remounts the subtree; that unmount/mount pair is what SSGOI
animates. By default, key and marker both follow the router pathname.

The route boundary is shipped in `@ssgoi/vue/nuxt`; no local component is needed.

## Plain Vue Router

Import the Vue Router entry and wrap the current RouterView component:

```vue
<!-- App.vue -->
<script setup lang="ts">
import { RouterView } from "vue-router";
import { Ssgoi } from "@ssgoi/vue";
import { SsgoiRouteBoundary } from "@ssgoi/vue/vue-router";
import { config } from "./ssgoi-config";

</script>

<template>
  <main class="relative z-0 min-h-dvh overflow-x-clip">
    <Ssgoi :config="config">
      <RouterView v-slot="{ Component }">
        <SsgoiRouteBoundary>
          <component :is="Component" />
        </SsgoiRouteBoundary>
      </RouterView>
    </Ssgoi>
  </main>
</template>
```

Verify: navigate `/` → any page slides in from the right; back slides out.

## Beyond the basics

For a persistent `/products` shell, collapse that family in the root boundary:

```vue
<script setup lang="ts">
const getRootTransitionId = (path: string) =>
  path === "/products" || path.startsWith("/products/")
    ? "/products"
    : path;
</script>

<SsgoiRouteBoundary :resolve="({ pathname }) => ({ id: pathname, key: getRootTransitionId(pathname) })">
  <NuxtPage />
</SsgoiRouteBoundary>
```

Then put a default pathname boundary only around the nested child:

```vue
<!-- pages/products.vue -->
<ProductHeaderAndTabs />
<SsgoiRouteBoundary>
  <NuxtPage />
</SsgoiRouteBoundary>
```

The stable outer key preserves the shell; the inner pathname boundary produces
child OUT/IN. Use the same two-lifetime pattern around a nested `<RouterView>`
in plain Vue Router.

- Full example: https://github.com/meursyphus/ssgoi/tree/HEAD/templates/nuxt
- Framework index: https://ssgoi.dev/llms/frameworks.txt

`@ssgoi/vue/nuxt` loads only its optional Nuxt 3/4 peer.
The root `@ssgoi/vue` import has no router dependency. The boundary accepts
`as`, DOM attributes, `routeKey`, and `resolve({ pathname })`. Return `{ id, key? }`;
key defaults to id and routeKey overrides it. Query/hash-only changes keep the
boundary by default. Keep the logical id current even when the key is stable.

Manual/custom-router guide: https://ssgoi.dev/llms/manual-boundaries.txt

Plain Vue Router users can import the same component from `@ssgoi/vue/vue-router`.
The Nuxt entry uses nuxt/app and does not install Vue Router as a separate peer.
