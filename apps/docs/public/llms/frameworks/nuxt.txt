# SSGOI with Vue Router and Nuxt

Experimental API: the router integration may change.

Nuxt wiring comes first; the plain Vue Router variant follows. Choose effects
from:
https://ssgoi.dev/llms/transitions.txt

```bash
npm install @ssgoi/vue
```

Shell class strings below are Tailwind shorthand. Without Tailwind, apply
`position: relative; z-index: 0; min-height: 100dvh; overflow-x: clip`. Use
`clip`, not `hidden`: `overflow-x: hidden` makes the wrapper the scroll
container, and scroll restore then targets the wrong element. Fall back to
`100vh` only where `dvh` is unsupported.

## Setup

Everything wires in the app root — one `<Ssgoi>` whose `framework.getRoute`
returns the router's current path, the shell classes, and the boundary component around
`<NuxtPage />`:

```vue
<!-- app.vue -->
<script setup>
import { Ssgoi, SsgoiLayoutBoundary } from "@ssgoi/vue";
import { config } from "~/utils/ssgoi-config";

const router = useRouter();
const framework = {
  getRoute: () => ({ pathname: router.currentRoute.value.path }),
};
</script>

<template>
  <main class="relative z-0 min-h-dvh overflow-x-clip">
    <Ssgoi :config="config" :framework="framework">
      <SsgoiLayoutBoundary>
        <NuxtPage />
      </SsgoiLayoutBoundary>
    </Ssgoi>
  </main>
</template>
```

`useRouter` is Nuxt's auto-import. Read `router.currentRoute`, the committed
router state, rather than Nuxt's delayed `useRoute()` value.
`SsgoiLayoutBoundary` throws if `<Ssgoi>` has no `framework`.

```ts
// utils/ssgoi-config.ts
import type { SsgoiConfig } from "@ssgoi/vue";
import { drill } from "@ssgoi/vue/view-transitions";

export const config: SsgoiConfig = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};
```

## The boundary component

A changed key remounts the subtree; that unmount/mount pair is what SSGOI
animates. By default, key and marker both follow the router pathname.

`SsgoiLayoutBoundary` is shipped in `@ssgoi/vue`; no local component is needed.

## Plain Vue Router

Pass the same `framework` from Vue Router's `useRouter` and wrap the current
RouterView component:

```vue
<!-- App.vue -->
<script setup lang="ts">
import { RouterView, useRouter } from "vue-router";
import { Ssgoi, SsgoiLayoutBoundary } from "@ssgoi/vue";
import { config } from "./ssgoi-config";

const router = useRouter();
const framework = {
  getRoute: () => ({ pathname: router.currentRoute.value.path }),
};
</script>

<template>
  <main class="relative z-0 min-h-dvh overflow-x-clip">
    <Ssgoi :config="config" :framework="framework">
      <RouterView v-slot="{ Component }">
        <SsgoiLayoutBoundary>
          <component :is="Component" />
        </SsgoiLayoutBoundary>
      </RouterView>
    </Ssgoi>
  </main>
</template>
```

Verify: navigate `/` → any page slides in from the right; back slides out.

## Beyond the basics

For a persistent `/products` shell, declare it in config and keep the root
boundary as it is:

```ts
// utils/ssgoi-config.ts
export const config: SsgoiConfig = {
  layouts: [{ paths: "/products/**" }],
  transitions: [/* ... */],
};
```

Then put a boundary only around the nested child:

```vue
<!-- pages/products.vue -->
<ProductHeaderAndTabs />
<SsgoiLayoutBoundary>
  <NuxtPage />
</SsgoiLayoutBoundary>
```

The root boundary (depth 0) keys every `/products` route by the one scope; the
inner boundary (depth 1) keys by the path and produces child OUT/IN. Use the
same two-lifetime pattern around a nested `<RouterView>`
in plain Vue Router.

- Full example: https://github.com/meursyphus/ssgoi/tree/HEAD/templates/nuxt
- Framework index: https://ssgoi.dev/llms/frameworks.txt

Nuxt 3/4 is supported. The root `@ssgoi/vue` import has no router or Nuxt
dependency; it calls the `getRoute` you pass. The boundary accepts
`as` and DOM attributes and takes no SSGOI props: its id is the route path and
its key is the `config.layouts` scope at its depth (the number of boundaries
above it), or the route path. Query/hash-only changes keep the boundary by
default.

Manual/custom-router guide: https://ssgoi.dev/llms/manual-boundaries.txt

`SsgoiRouteBoundary` from `@ssgoi/vue/nuxt` or `@ssgoi/vue/vue-router` still
works but is deprecated and will be removed in 8.0.0.
