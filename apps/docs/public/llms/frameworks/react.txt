# SSGOI with React

Use SSGOI with React independently of your router. Tell the provider how to read your router’s route through framework, and SsgoiLayoutBoundary connects it to a page lifetime.

Install @ssgoi/react. Keep one provider above the changing page region.

## Common setup

Install @ssgoi/react. Keep one provider and a stable config above routed content. The surrounding layout supplies position: relative, z-index: 0, min-height: 100dvh, and overflow-x: clip.

```tsx
import type { ReactNode } from "react";
import { Ssgoi, type SsgoiConfig } from "@ssgoi/react";
import { drill } from "@ssgoi/react/view-transitions";

const config: SsgoiConfig = {
  transitions: [{ on: "/**", except: "/", transition: drill() }],
};

export function SsgoiProvider({ children }: { children: ReactNode }) {
  return <Ssgoi config={config}>{children}</Ssgoi>;
}
```

## Transition state

A page that scrolls itself on arrival (anchor jump, scrollIntoView) fights
the animation. Read the provider's transition state and act once it is idle.
The status is `idle` or `transitioning`; while transitioning it also carries
`from`, `to` and `direction`. It flips as soon as the navigation is paired,
one microtask after the DOM changed, and returns to `idle` when the run
releases, the same span the scroll-input lock covers.

```tsx
import { useEffect } from "react";
import { useSsgoiTransition } from "@ssgoi/react";

export function Comments({ anchor }: { anchor: string }) {
  const { status } = useSsgoiTransition();
  useEffect(() => {
    if (status !== "idle") return;
    document.getElementById(anchor)?.scrollIntoView();
  }, [status, anchor]);
  return null;
}
```

## Connect a router

Pass `framework` to `<Ssgoi>`, then wrap routed children in `SsgoiLayoutBoundary`
from `@ssgoi/react`. `framework.useRoute` is a hook you write with your router's
own hooks: it returns the current route (`{ pathname, ...anything }`) or `null`
while the router is not ready, which renders `fallback`. The function form of the
boundary's `boundary` prop receives that route object as-is. Keep the object at module scope so it stays stable. `SsgoiLayoutBoundary` throws if the nearest `<Ssgoi>` has no
`framework`. The router guides below show the object for each router.

```tsx
import { Ssgoi, SsgoiLayoutBoundary, type SsgoiFramework } from "@ssgoi/react";

const framework: SsgoiFramework = {
  useRoute: () => ({ pathname: useYourRouterPathname() }),
};

<Ssgoi config={config} framework={framework}>
  <SsgoiLayoutBoundary>{children}</SsgoiLayoutBoundary>
</Ssgoi>
```

## Using another router

Any router works without a dedicated integration: return its committed pathname from `useRoute`, read in the same render as its children. You can also skip `framework` and render a keyed DOM boundary yourself. The Route boundaries guide explains the general pattern.
