# SSGOI with SvelteKit

Use one config and one `<Ssgoi>` in the root layout.

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  import { Ssgoi } from "@ssgoi/svelte";
  import { config } from "$lib/ssgoi-config";

  let { children } = $props();
</script>

<main class="relative z-0 min-h-dvh overflow-x-clip">
  <Ssgoi {config}>{@render children()}</Ssgoi>
</main>
```

## Page boundary

Put the transition id on the routed page root.

```svelte
<!-- src/routes/posts/[id]/+page.svelte -->
<article data-ssgoi-transition="/posts/{post.id}">
  <!-- page -->
</article>
```

## Persistent layout

A route layout may own a boundary. It stays mounted while its child pages
change.

```svelte
<!-- src/routes/products/+layout.svelte -->
<script>
  import { page } from "$app/stores";
  let { children } = $props();
</script>

<section data-ssgoi-transition={$page.url.pathname}>
  <ProductTabs />
  {@render children()}
</section>
```

Keep a child page boundary for tab-to-tab transitions:

```svelte
<main data-ssgoi-transition={$page.url.pathname}>
  <!-- tab content -->
</main>
```

When the layout and page leave together, SSGOI uses the outer changed
boundary. When only the page changes, it uses the page boundary.
