# SSGOI - hero transition

Shared element transition. The same logical object (a thumbnail, an avatar, a card image) is tweened in size and position from one page to the next. Use when the user should feel they're following the *same thing* across pages.

Setup guide: https://ssgoi.dev/llms.txt

## Behavior

The element marked as the "list-side" entry on the source page is tweened in position and size to match its "detail-side" counterpart on the destination page. The rest of the page handles its surrounding chrome based on `type`.

If a key has no match on the other side, that element falls back gracefully (no animation on it).

`type` picks how the surrounding chrome behaves around the shared element:

- **`type: "static"`** (default) — the incoming page's chrome snaps in; a temporary shared-element clone morphs via clip-path inset + uniform scale. Use when the destination chrome should feel like an *extension* of the list page (e.g., gallery → fullscreen viewer where the rest of the screen is just dark).
- **`type: "fade"`** — both pages cross-fade as whole surfaces while a temporary shared-element clone morphs above them. Use when each side has its own chrome (e.g., a list page and a detail page with its own back button, title bar, or meta panel).

## Signature

```ts
import { hero } from "@ssgoi/react/view-transitions";

hero({
  paths: readonly string[];        // routes participating in hero transitions
  type?: "static" | "fade";        // default: "static"
  variant?: "default";             // reserved — only "default" today
  options?: {};                    // reserved — no fields yet
}): SsgoiPathTransition[];
```

## Required: matching enter/exit keys

Mark the destination-side ("detail") element with `data-hero-enter-key` and the source-side ("list") element with `data-hero-exit-key`. Both must use the **same** stable string value — use the item's id, not its index.

```tsx
// List page (/items)
{items.map((item) => (
  <Link key={item.id} href={`/items/${item.id}`}>
    <img
      data-hero-exit-key={`item-${item.id}`}
      src={item.thumbnail}
      width={item.width}
      height={item.height}
      className="object-cover"
    />
  </Link>
))}

// Detail page (/items/[id])
<img
  data-hero-enter-key={`item-${id}`}
  src={fullImage}
  width={photo.width}
  height={photo.height}
  className="object-contain"
/>
```

The transition matches enter/exit pairs in both navigation directions — forward (list→detail) and back (detail→list) — without extra configuration.

## Automatic image geometry

Hero automatically resolves image geometry when the keyed element is an `<img>`, or when a keyed wrapper contains exactly one direct `<img>` child. It reads intrinsic dimensions or standard `width` / `height` attributes, computed centered `object-fit: cover|contain`, and a simple uniform CSS border radius.

```tsx
// The wrapper defines the visible crop and radius; the child defines media.
<div
  data-hero-exit-key={`item-${id}`}
  className="overflow-hidden rounded-xl"
>
  <img
    src={photo.src}
    width={photo.width}
    height={photo.height}
    className="h-full w-full object-cover"
  />
</div>
```

For wrapper inference, the image must be a direct child and the wrapper must use `overflow: hidden` or `overflow: clip` for its radius to define the visible window. Multiple/deep images, `<picture>` / `<video>`, unsupported fits, custom object positions, unavailable dimensions, complex radii, or mismatched endpoint ratios safely fall back to the original bounding-box transition.

## Legacy: `data-hero-key`

The original `data-hero-key` attribute is still supported for backwards compatibility — putting the same `data-hero-key` value on both pages will animate that pair. New code should use the `data-hero-enter-key` / `data-hero-exit-key` pair instead; the single-key form is treated as a fallback and is only consulted when no enter/exit pair matched.

## Usage

```ts
const config = {
  transitions: [
    // List ↔ detail where the detail screen is "just a fullscreen viewer"
    hero({ paths: ["/items", "/items/*"] }),

    // List ↔ detail where each page has its own chrome (back button, meta)
    hero({ paths: ["/photos", "/photos/*"], type: "fade" }),
  ],
};
```
