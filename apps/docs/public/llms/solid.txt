# SSGOI - Solid / SolidStart setup

Framework-specific setup for `@ssgoi/solid`. The `SsgoiConfig` shape, transition catalog, and troubleshooting are shared across frameworks — read https://ssgoi.dev/llms.txt for those.

## Installation

```bash
npm install @ssgoi/solid
```

Reference template: https://github.com/meursyphus/ssgoi/tree/main/templates/solidstart

## Layout setup

Same three rules as every framework (details in llms.txt):

1. Pick the scroll element whose position SSGOI should preserve.
2. Put `relative z-0` (plus `overflow-x-clip` for horizontal transitions) on the outer element that wraps `<Ssgoi>`.
3. Mark routed content with `data-ssgoi-transition="..."` directly on each routed page.

## SolidStart example

```tsx
// src/app.tsx
import { Router } from "@solidjs/router";
import { FileRoutes } from "@solidjs/start/router";
import { Ssgoi } from "@ssgoi/solid";
import { zoom } from "@ssgoi/solid/view-transitions";

const config = {
  transitions: [
    {
      from: "/gallery",
      to: "/gallery/*",
      transition: zoom({ type: "expand" }),
    },
  ],
};

export default function App() {
  return (
    <Router
      root={(props) => (
        <main class="relative z-0 min-h-dvh overflow-y-auto overflow-x-clip">
          <Ssgoi config={config}>{props.children}</Ssgoi>
        </main>
      )}
    >
      <FileRoutes />
    </Router>
  );
}

// src/routes/gallery/index.tsx
export default function Gallery() {
  return <section data-ssgoi-transition="/gallery">{/* content */}</section>;
}
```

The `data-ssgoi-transition` value can be a hard-coded logical page id; it only needs to match the `on`, `from`, `to`, or `ordered` route patterns in `SsgoiConfig`. For dynamic routes, match with wildcards in the config (`/post/*`).
