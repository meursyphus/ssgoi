# SSGOI hero transition

Use when the user should follow the same logical object, such as a thumbnail or
avatar, from one page to another.

Catalog: https://ssgoi.dev/llms/transitions.txt

## Props

```ts
import { hero } from "@ssgoi/react/view-transitions";

hero({
  type?: "static" | "fade";  // default: "static"
  variant?: "default" | "smooth";  // default: "default"
  options?: Record<string, never>;
}): TransitionConfig;
```

- `static`: morph the actual shared visual while incoming content appears immediately.
- `fade`: fade out the outgoing page and fade in destination sibling content and
  ancestor background colors. Shared-image crossfading runs independently of
  these content fades. CSS background images/gradients on ancestors keep their
  authored rendering. No extra option is needed.
- `variant: "smooth"`: use a softer follower spring for the element morph;
  this can be combined with either type.

## Required markup

Use the same stable value on the list-side and detail-side elements. Hero can
animate multiple distinct pairs in one transition:

```tsx
<img data-hero-exit-key={item.id} src={item.thumbnail} />
<img data-hero-enter-key={item.id} src={item.full} />
```

- Keep each key unique on each page. If a key is duplicated, the first element
  in DOM order is used.
- Pairs without a matching key on the other page are skipped.
- If no matching pair exists, Hero is a no-op.

## Automatic image geometry

A keyed image or a wrapper with one direct image child automatically supplies
intrinsic dimensions and centered CSS object-fit: cover/contain. Clipping
ancestors inside the page supply rectangular overflow crops and simple uniform
pixel radii, including when the key is on an image inside a rounded wrapper.
Partially visible cards retain their surviving rounded corners. Nested scroll
and translated rows are measured at their visible positions. No data-hero-radius
is needed; legacy radius values remain explicit overrides.

Inference stays conservative for ambiguous media, incompatible intrinsic
ratios, custom object-position, and complex clipping. Bordered clipping
ancestors, reserved scrollbar gutters, nonuniform/percentage radii, and clips
that cut partway through a rounded corner retain the existing geometry path.

## Example

```ts
const config = {
  transitions: [
    {
      from: "/items",
      to: "/items/*",
      transition: hero({ type: "fade" }),
    },
  ],
};
```

Route rules: https://ssgoi.dev/llms/route-rules.txt

## In-page rendering and clipping

Hero enter (exit-key to enter-key, usually list to detail) animates the actual
destination visual in its existing parent and adds a temporary copy of the source
visual beside it. Both follow the same geometry:
the source fades out while the destination fades in, even when the images or
intrinsic aspect ratios differ. This applies to every type/variant and both
navigation directions, without an extra option.

On enter, Hero does not reparent the destination visual, insert a placeholder,
or change its position, width, height, margins, flex, or object-fit. Only paint
properties (transform, clip-path, border-radius, opacity) change, expressed
against the visual's own box, including images whose fitted content is larger
than that box. No transition-state attribute is added.

The source copy is an absolutely positioned, inert sibling of the destination.
It normally goes right before the destination, paints below it, and stays
opaque while the destination fades in over it, so the flight stays covered
wherever the destination cannot paint itself. If that position would move
something through structural selectors (`:first-child`, Tailwind v3
`space-y-*`), the copy goes right after the destination and fades out over it
instead. Completion removes the copy and restores the original inline styles.
Overlay content such as a rounded detail sheet retains its authored stacking
order.

Hero exit (enter-key to exit-key, usually detail to list) crossfades temporary
copies of both visuals in a separate image layer above both pages. The layer
escapes list chrome and nested carousel clipping while preserving the measured
crop and corner geometry. Both real endpoints stay hidden until completion;
cleanup removes the layer and restores their original opacity.

Endpoint keys determine enter/exit independently of history direction. Legacy
data-hero-key pairs use backward history navigation to select the exit layer.

Layout is always authored by the application. A fixed-ratio frame can contain an
image positioned absolutely from the initial render; the frame then owns its
height before, during, and after the transition. Keep overflow rules static:
the engine never changes overflow, containment, or scroll positions.

Where the destination cannot paint, the source copy fills that part of the
flight until the crop closes:

- Cover content past the image's own box. Browsers clip a replaced element at
  its box by default. Chromium paints beyond it when the image has static
  `overflow: visible` (and logs a console notice); WebKit always clips.
- Anything outside an unpositioned clipping ancestor, such as a Tailwind
  `overflow-hidden rounded-lg` cell around the image. The copy escapes it; the
  real image stays clipped until it lands.

A positioned clipping ancestor (for example `relative overflow-hidden`, or a
`fill` image frame) clips the copy too, so the flight is only visible inside
that frame. When the image flies in from outside such a frame, let the image
own its crop and corners instead. Hero replaces the clip-path while it runs,
restores the authored one on completion, and reads the resting corner from
`border-radius`, so keep both radii equal:

```css
.photo {
  border-radius: 8px;
  clip-path: inset(0 round 8px);
}
```

Changed after 7.3.2: the destination is no longer resized and absolutely
positioned during the flight, and the `data-hero-transitioning` attribute is
gone. Rules such as `.gallery:has([data-hero-transitioning]) { overflow: visible }`
no longer match and can be removed; an unpositioned clipping wrapper needs no
rule, and a positioned one needs the image-owned crop above.
