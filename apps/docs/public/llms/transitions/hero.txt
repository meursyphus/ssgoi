# SSGOI hero transition

Use when the user should follow the same logical object, such as a thumbnail or
avatar, from one page to another.

Catalog: https://ssgoi.dev/llms/transitions.txt

## Props

```ts
import { hero } from "@ssgoi/react/view-transitions";

hero({
  type?: "static" | "fade";  // default: "static"
  variant?: "default" | "smooth";  // default: "default"
  options?: Record<string, never>;
}): TransitionConfig;
```

- `static`: morph the actual shared visual while incoming content appears immediately.
- `fade`: fade out the outgoing page and fade in destination sibling content and
  ancestor background colors. Shared-image crossfading runs independently of
  these content fades. CSS background images/gradients on ancestors keep their
  authored rendering. No extra option is needed.
- `variant: "smooth"`: use a softer follower spring for the element morph;
  this can be combined with either type.

## Required markup

Use the same stable value on the list-side and detail-side elements. Hero can
animate multiple distinct pairs in one transition:

```tsx
<img data-hero-exit-key={item.id} src={item.thumbnail} />
<img data-hero-enter-key={item.id} src={item.full} />
```

- Keep each key unique on each page. If a key is duplicated, the first element
  in DOM order is used.
- Pairs without a matching key on the other page are skipped.
- If no matching pair exists, Hero is a no-op.

## Automatic image geometry

A keyed image or a wrapper with one direct image child automatically supplies
intrinsic dimensions and centered CSS object-fit: cover/contain. Clipping
ancestors inside the page supply rectangular overflow crops and simple uniform
pixel radii, including when the key is on an image inside a rounded wrapper.
Partially visible cards retain their surviving rounded corners. Nested scroll
and translated rows are measured at their visible positions. No data-hero-radius
is needed; legacy radius values remain explicit overrides.

Inference stays conservative for ambiguous media, incompatible intrinsic
ratios, custom object-position, and complex clipping. Bordered clipping
ancestors, reserved scrollbar gutters, nonuniform/percentage radii, and clips
that cut partway through a rounded corner retain the existing geometry path.

## Example

```ts
const config = {
  transitions: [
    {
      from: "/items",
      to: "/items/*",
      transition: hero({ type: "fade" }),
    },
  ],
};
```

Route rules: https://ssgoi.dev/llms/route-rules.txt

## In-page rendering and clipping

Hero animates the actual destination visual in its existing parent and adds a
temporary copy of the source visual beside it. Both follow the same geometry:
the source fades out while the destination fades in, even when the images or
intrinsic aspect ratios differ. This applies to every type/variant and both
navigation directions, without an extra option.

An empty, aria-hidden placeholder reserves a flow image's original layout space
while it uses its fitted content size. Completion removes the copy and placeholder
and restores the original styles. Overlay content such as a rounded detail sheet
retains its authored stacking order.

The library never changes ancestor overflow, containment, or scroll positions.
Those clipping choices belong to the application. If a crop should open during
the transition, opt in at that specific wrapper:

```css
.gallery:has([data-hero-transitioning]) {
  overflow: visible;
}
```

The marker is on the real animated visual and is restored on completion. It can
also be used on a caller-owned carousel viewport. The caller remains responsible
for clipping other carousel items and preserving native scroll-container layout.
