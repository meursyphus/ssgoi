# SSGOI pattern: persistent bottom navigation

Use one `<Ssgoi>` and one config. Put transition boundaries in layouts.

## Goal

- Tab → tab: animate page content; keep the bottom nav still.
- Tab → detail: animate the whole tab shell; the bottom nav leaves with it.
- Detail → tab: restore the whole tab shell.

## Route structure

Next.js route groups change layout lifetime without changing URLs.

```text
app/
  layout.tsx
  ssgoi-provider.tsx
  ssgoi-transition-boundary.tsx
  (tabs)/
    layout.tsx
    page.tsx
    collections/page.tsx
    create/page.tsx
  (detail)/
    layout.tsx
    photo/[id]/page.tsx
```

The root layout contains the only SSGOI instance:

```tsx
// app/ssgoi-provider.tsx
"use client";

import { Ssgoi } from "@ssgoi/react";
import { axis, drill } from "@ssgoi/react/view-transitions";

const config = {
  transitions: [
    {
      ordered: ["/", "/collections", "/create"],
      transition: axis({ type: "x", variant: "snappy" }),
    },
    {
      on: "/photo/*",
      transition: drill(),
    },
  ],
};

export function SsgoiProvider({ children }) {
  return <Ssgoi config={config}>{children}</Ssgoi>;
}
```

## Boundary utility

`scope` is application code. It maps the real pathname to a React key.
It is not part of `SsgoiConfig`.

```tsx
// app/ssgoi-transition-boundary.tsx
"use client";

import { usePathname } from "next/navigation";

export function SsgoiTransitionBoundary({
  children,
  scope = (pathname) => pathname,
  className,
}) {
  const pathname = usePathname();

  return (
    <div
      key={scope(pathname)}
      data-ssgoi-transition={pathname}
      className={className}
    >
      {children}
    </div>
  );
}
```

Rules:

- Return the pathname to remount on every route change.
- Return the same key to keep a layout mounted.
- Always keep the real pathname in `data-ssgoi-transition`.

## Tab layout

```tsx
// app/(tabs)/layout.tsx
import { SsgoiTransitionBoundary } from "../ssgoi-transition-boundary";

export default function TabsLayout({ children }) {
  return (
    <SsgoiTransitionBoundary scope={() => "tabs-shell"}>
      <header>Photos</header>

      <SsgoiTransitionBoundary>
        {children}
      </SsgoiTransitionBoundary>

      <BottomNav />
    </SsgoiTransitionBoundary>
  );
}
```

The outer key is stable while the `(tabs)` layout survives. The inner key is
the pathname.

## Detail layout

```tsx
// app/(detail)/layout.tsx
import { SsgoiTransitionBoundary } from "../ssgoi-transition-boundary";

export default function DetailLayout({ children }) {
  return (
    <SsgoiTransitionBoundary>
      {children}
    </SsgoiTransitionBoundary>
  );
}
```

## What remounts

| Navigation | Outer tab shell | Inner tab content | Bottom nav |
| --- | --- | --- | --- |
| `/` → `/collections` | stays | remounts | stays |
| `/collections` → `/photo/1` | leaves | leaves with parent | leaves |
| `/photo/1` → `/collections` | enters | enters with parent | enters |

When a parent and nested boundary enter or leave in the same DOM mutation,
SSGOI uses the outer changed boundary. If the parent remains mounted, the
changed child boundary owns the transition.

## Do not

- Do not create a nested `<Ssgoi>`.
- Do not put one pathname-keyed boundary around every route at the root.
- Do not render the nav outside the tab shell if it must leave on detail
  navigation.
- Do not use a stable transition id. Keep only the React key stable; the
  transition id must remain the real pathname.
