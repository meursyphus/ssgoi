# SSGOI - zoom transition

Card-to-detail expansion. The tapped card grows from its grid position into the detail viewport (or to a target element). Use for **gallery → lightbox**, image grids, expandable cards, and "tap to expand" flows.

Setup guide: https://ssgoi.dev/llms.txt

## Behavior

Three `type` flavors decide what the source card does:

- **`static`** (default): the source card morphs to the size/position of the destination element (without filling the viewport). Use when the detail isn't full-screen — e.g. a modal popping out of its tile in place.
- **`expand`**: the source card grows to fill the destination viewport. Background fades. On exit, it collapses back into the card.
- **`blur`**: the source card stays anchored while the background blurs and the detail rises into focus. Quieter than `expand`.

One `variant` flavor decides how the surrounding pages handle opacity:

- **`default`**: no extra fade — only the card / background work defined by `type` runs.
- **`fade`**: outgoing and incoming pages cross-fade alongside the card morph. Useful when content beyond the card differs noticeably between source and detail.

If no matching `enter` / `exit` element is found, the transition is a no-op.

## Signature

```ts
import { zoom } from "@ssgoi/react/view-transitions";

zoom({
  paths: readonly string[];
  type?: "static" | "expand" | "blur";   // default: "static"
  variant?: "default" | "fade";          // default: "default"
  options?: {};                          // reserved — no fields yet
}): SsgoiPathTransition[];
```

> Deprecated: `fade: true` — use `variant: "fade"` instead.

## Required: matching `data-zoom-exit-key` / `data-zoom-enter-key`

Different attribute names describe stable semantic roles in both navigation directions:
- **List/card side** marks the collapsed source element with `data-zoom-exit-key="<key>"`.
- **Detail/expanded side** marks the expanded destination element with `data-zoom-enter-key="<key>"`.
- The key VALUES must match across the two pages.

```tsx
// Gallery page (/grid) — the card being tapped
{photos.map((p) => (
  <Link key={p.id} href={`/photo/${p.id}`}>
    <img
      data-zoom-exit-key={`photo-${p.id}`}
      src={p.thumb}
      width={p.width}
      height={p.height}
      className="aspect-square object-cover"
    />
  </Link>
))}

// Detail page (/photo/[id]) — the destination
<img
  data-zoom-enter-key={`photo-${id}`}
  src={fullImage}
  width={photo.width}
  height={photo.height}
  className="h-full w-full object-contain"
/>
```

## Automatic image geometry

Like Hero, Zoom resolves a directly keyed `<img>` or exactly one direct `<img>` child inside a keyed wrapper. It reads intrinsic dimensions or standard `width` / `height` attributes and computed centered `object-fit: cover|contain`, then maps content to content and inverse-projects the collapsed crop into the detail page.

A keyed wrapper with `overflow: hidden|clip` supplies the visible crop and a simple uniform CSS radius; its single direct image supplies the media ratio and fit. Both endpoints must resolve to compatible images, and the destination must be able to render the projected source crop. Otherwise Zoom preserves its original bounding-box animation. Ambiguous/deep images, `<picture>` / `<video>`, unsupported fits, custom object positions, unavailable dimensions, or complex radii also fall back safely.

## Usage

```ts
const config = {
  transitions: [
    zoom({ paths: ["/grid", "/photo/*"], type: "expand" }),
    zoom({ paths: ["/feed", "/post/*"], type: "static", variant: "fade" }),
  ],
};
```
